# How this profile works

This repo is a GitHub **profile README**. A public repo whose name matches your username (`byw1/byw1`) puts its `README.md` at the top of your profile page. Everything else in the repo exists to feed that one file.

Nothing here relies on a third-party card service. The images are SVGs made in this repo, and a GitHub Action keeps the live numbers fresh. The badges are the only exception: they come from [shields.io](https://shields.io).

## What's on the page, and where it comes from

| Section | File | Made by | Updates |
| --- | --- | --- | --- |
| Signature banner | `assets/banner.svg` | `scripts/build-assets.py` | When you rebuild |
| Project cards | `assets/project-*.svg` | `scripts/build-assets.py` | When you rebuild |
| Favorite reads shelf | `assets/bookshelf.svg` | `scripts/build-assets.py` | When you rebuild |
| Tech stack badges | inline in `README.md` | shields.io | Never (static) |
| Streaks + top languages | `stats.svg` on the `output` branch | `scripts/stats.py`, run by the Action | Every 12 hours |
| "X contributions in the last year" | `contributions*.svg` on `output` | the Action | Every 12 hours |
| Contribution snake | `snake*.svg` on `output` | [Platane/snk](https://github.com/Platane/snk), run by the Action | Every 12 hours |

### Two kinds of images

**Static SVGs (`assets/`)** are committed to the repo. They are generated by `scripts/build-assets.py`, so edit the script and rebuild; never hand-edit the SVGs. Each one is fully self-contained, because GitHub serves README images through its image proxy as a plain `<img>`, which can't load outside fonts or pictures. That means:

- Poppins is subset to just the characters used and embedded as base64 woff2.
- App icons are embedded as base64 PNGs (sources in `scripts/icons/`).
- Animations are CSS inside the SVG. GitHub does play them, and each image animates when it scrolls into view.

**Live SVGs (the `output` branch)** are written by `.github/workflows/snake.yml` every 12 hours, on every push, and whenever you run it by hand from the Actions tab. The README links to them with `raw.githubusercontent.com/byw1/byw1/output/...` URLs. The workflow force-pushes the `output` branch each run, so never put anything else there.

## Making changes

### Change a project card, the shelf or the banner

```bash
pip install fonttools brotli pillow
python3 scripts/build-assets.py        # rewrites assets/*.svg
```

- **Projects** are the `PROJECTS` list in `scripts/build-assets.py`. Each has a slug (the icon is `scripts/icons/<slug>.png`, 256×256 works best), a name, a status pill, a two-line tagline, two accent colours and tags. Add the matching `<a><img></a>` line in the README's projects block too. Cards link to the project's GitHub repo.
- **Books** are the `BOOKS` list in the same file.
- **The signature** is two SVG paths in `scripts/signature.json`. The banner and the site's intro both draw them. To use your own, trace your signature as one or two paths (in a viewBox of about 900×350) and replace the file.

The first run downloads Poppins from Google Fonts into `scripts/.fonts/`, which git ignores.

### Change the tech stack badges

They're plain shields.io URLs in `README.md`:

```
https://img.shields.io/badge/<Label>-000000?style=for-the-badge&logo=<simple-icons slug>&logoColor=<hex>
```

Find logo slugs at [simpleicons.org](https://simpleicons.org).

### Change the stats card

Edit `scripts/stats.py`, push, and the Action redraws it. It reads:

- **Streaks** from the contribution calendar, across every year you've had contributions. Days later than today are ignored (the calendar runs to Dec 31). Today counts toward the current streak only once it has a contribution, the same way GitHub counts it.
- **Top languages** from your **public**, non-fork repos. The Action's built-in token can't see private repos. To include them, create a fine-grained personal access token with read-only access to your repos' metadata and contents, save it as a repo secret, and pass it as `GH_TOKEN` in the workflow instead of `secrets.GITHUB_TOKEN`.

To try it locally: `GH_TOKEN=<token> python3 scripts/stats.py <login> stats.svg`.

## Make one like it for yourself

1. Create a **public** repo named exactly your username.
2. Copy this repo in.
3. Replace `scripts/signature.json`, `scripts/icons/`, and the `PROJECTS` and `BOOKS` lists, then run `scripts/build-assets.py`.
4. Change `byw1` to your username in the `raw.githubusercontent.com` URLs in `README.md`. The workflow already uses whichever account owns the repo.
5. Push. The Action runs straight away, and the live images appear once it finishes, after about a minute.
6. If the Action fails to push the `output` branch, go to **Settings → Actions → General** and set workflow permissions to **Read and write**.

If your contribution graph counts private work, turn on **Include private contributions on my profile** in your GitHub profile settings. The streak card and the snake then count it too.

## Gotchas

- **Fonts bleeding between images:** Chrome shares one font cache across every SVG on a page, keyed by font-family name. Two SVGs that each embed a different subset under the same name can borrow each other's glyphs and draw blank text. `build-assets.py` prefixes every family name with the file's name to prevent this. Keep that step if you add new SVGs.
- **The `dist/` permission error:** `Platane/snk` runs in Docker and leaves `dist/` owned by root. That's why the workflow runs `sudo chown` before writing more files into it.
- **Stale images after a run:** `raw.githubusercontent.com` caches for about 5 minutes, so a fresh run can take that long to show on the profile.
